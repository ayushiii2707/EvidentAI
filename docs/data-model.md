# Data model (CP2)

PostgreSQL 16 + pgvector, one database. Schema: `migrations/versions/0001_initial_schema.py`
(table DDL autogenerated from `evidentai/db/models.py`, then reviewed; triggers, RLS and
grants hand-written). A test fails if the models and the migrated schema drift apart.

## Tables created now

Only what CP2 and the next checkpoint (CP3, ingestion) need.

| Table | Scope | Purpose |
|---|---|---|
| `users` | global | Identity only; credentials arrive in CP7 |
| `workspaces`, `memberships` | tenant | Tenancy; role `owner` or `member` |
| `products`, `releases` | tenant | What is documented, and its versions (`sort_key` orders "2.4" < "3.0") |
| `documents` | tenant | Logical document (e.g. `auth-guide`) of a product |
| `document_versions` | tenant | One uploaded file of a document for one release, with lifecycle status |
| `sections`, `chunks` | tenant | Parsed structure and retrievable text, with page/line provenance |
| `embedding_models` | global | Embedding identity: name, revision, dimensions, normalization version |
| `embeddings` | tenant | Vector keyed by (workspace, model, normalized content hash) |
| `ingestion_jobs` | tenant | One job per version; state, attempts, lease (used by the CP3 worker) |
| `scope_snapshots`, `scope_snapshot_versions` | tenant | Pinned set of versions an investigation may read |

## Integrity rules enforced by the database

- **Composite foreign keys carry `workspace_id`** (and `product_id` for versions), so a row
  cannot reference a parent in another workspace, and a version's release must belong to
  its document's product. This holds even for the owner role, which bypasses RLS.
- **Lifecycle trigger** on `document_versions` mirrors `evidentai/db/lifecycle.py`:

  ```
  pending → parsing → indexing → active → superseded
  pending, failed, active, superseded → deleted → purged
  parsing, indexing → failed → pending (retry)
  ```

  Versions must be inserted as `pending`. Identity columns (workspace, product, document,
  release, sha256) are immutable. A test checks all 64 status pairs against the Python
  table, with the repository bypassed.
- **At most one `active` version** per (document, release): partial unique index.
  `activate()` supersedes the previous active version in the same transaction.
- **Content writes** (sections, chunks) are only accepted while the version is `indexing`.
  CP3 relies on this: nothing becomes visible until activation.
- **Duplicate upload:** unique (document, release, sha256). Re-uploading identical bytes
  returns the existing version.
- **Embedding dimensions** must match the model (trigger), since the vector column has no
  fixed dimension and several models can coexist.

## Pinned scopes, retention and deletion

A **scope snapshot** records the versions that were `active` for its releases at the moment
it was created, in a single `INSERT … SELECT`. Later uploads, replacements and deletions do
not change it. The database refuses to pin a non-active version, a version outside the
snapshot's product or releases, or to add to a closed snapshot. Scope is immutable, and a
closed snapshot cannot be reopened.

Retention policy:

| Status | Visible to new snapshots | Content stored | Notes |
|---|---|---|---|
| `active` | yes | yes | |
| `superseded` | no | yes | Old snapshots keep reading it |
| `deleted` | no | yes | Hidden immediately; content kept for open snapshots |
| `purged` | no | **no** | Sections and chunks removed; version row kept as tombstone |

- **Purge is refused** (`VersionPinned`) while any **open** snapshot pins the version.
- After purge, a closed snapshot still lists the version, with `content_available = False`.
  Reports built from it must say the evidence was deleted, not silently drop it.
- A version row cannot be hard-deleted while any snapshot references it (FK). Deleting a
  whole workspace still cascades everything.
- **Not decided yet:** how long `superseded` and `deleted` content is kept before an
  automatic purge, and when snapshots are closed. Both need a policy decision. Today
  purging is explicit, and the stored file in object storage must be removed by the
  caller (no object storage exists yet).

## Embedding reuse

- Key: `(workspace_id, model_id, content_hash)`.
- `content_hash = sha256("n1" ‖ NFKC + whitespace-collapsed embed_text)`. Case and
  punctuation are kept on purpose: `capture` vs `Capture`, `/v2/` vs `/v3/`.
- `model_id` identifies name + revision + normalization version. Changing any of them
  creates a new model row, so stale vectors are never reused.
- `embed_text` excludes the document title (which contains the version label), so an
  unchanged section in v2.4 and v3.0 has the same hash and is embedded once. A test checks
  this on the corpus: the Pagination section is shared, while Rate Limits differs.
- **Provenance stays independent.** The embedding row has no document-version column.
  Each chunk row records its own version, page, line and section, and joins to the
  embedding by hash.
- **Scoped per workspace**, not global. A global cache would let one tenant infer, through
  cache hits, that another tenant holds identical text. The cost is no cross-tenant reuse.
- Unreferenced embeddings are not garbage-collected yet (deferred).

## Tenant isolation: layers and trust boundaries

| Layer | Mechanism | Protects against | Does NOT protect against |
|---|---|---|---|
| 1. Membership | `workspace_transaction` checks `memberships` before handing out a repository | A user requesting a workspace they don't belong to | Code that skips `workspace_transaction` |
| 2. Repository filters | Every query has `workspace_id = scope.workspace_id`; other workspaces' ids → `NotFound` | Wrong-tenant ids passed to repository methods | Raw SQL outside the repository |
| 3. Row-level security | Policies on all 12 workspace-scoped tables compare to transaction-local `app.workspace_id`; app role is not owner and has no `BYPASSRLS` | Forgotten `WHERE` clauses, stray raw SQL, a missing setting (fails closed: no rows), pooled-connection leakage | Code or injected SQL **running as the app role that sets `app.workspace_id` itself**. RLS trusts the setting |
| 4. Composite FKs | `workspace_id` in every parent reference | Cross-workspace references, even from the owner role | Reads |

What sits outside all four layers:

- **The owner role** (migrations) and superusers bypass RLS. The application must never
  connect as the owner. `FORCE ROW LEVEL SECURITY` is not set, because the owner runs
  migrations.
- **SQL injection** as the app role could call `set_config` and read any workspace. The
  defence is parameterized SQL everywhere (SQLAlchemy); RLS does not cover it.
- **Global tables:** the app role has no grant on `users` (it would expose every tenant's
  emails), and read-only access to `embedding_models`.
- **Side channels** (timing, unique-constraint errors) are not addressed.
- `WorkspaceScope` is a plain dataclass. Python cannot stop code from constructing one
  without a membership check, which is why layer 3 does not trust it.

Bypass paths tested (`tests/db/test_isolation.py`):
- no setting → 0 rows in every table
- raw `SELECT` without `WHERE` → own rows only
- inserting, updating or moving rows into another workspace
- setting leakage across pooled transactions
- a malformed setting fails closed
- `SET ROLE`, `DISABLE ROW LEVEL SECURITY`, `DROP POLICY`, `TRUNCATE`, `CREATE TABLE` and
  reading `users` are denied
- the repository filters hold with RLS bypassed
- a table with `workspace_id` but no RLS policy fails the meta-test

One test, `test_documented_boundary_rls_trusts_the_workspace_setting`, asserts the known
gap rather than hiding it.

## Test database safety

Tests use a separate database, `evidentai_test`, which is dropped and recreated each
session; a dedicated `evidentai_migration_test` is used for round-trips. Destructive helpers
(`evidentai/db/safety.py`) refuse to run unless both of these hold:
- the URL names a local host and a database ending in `_test`;
- the server-reported `current_database()` matches it.

A test connects to the real dev database and confirms the guard fires before any `TRUNCATE`.
